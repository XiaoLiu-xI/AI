## 4. 中文 MiniGPT：老舍风格生成（曲折探索）

### 4.1 数据集选择与清理
选定老舍公版作品：《骆驼祥子》+《四世同堂》，总计约 82 万字符。
**教训：千万不要用正则批量删除低频字符！** 中文异体字、方言字一旦被过滤，就会变成 ? 乱码，导致大量文字缺失。正确做法：只删除每行开头的空格。

### 4.2 中文训练脚本

**第一次尝试（失败：严重过拟合）**
- 数据：12.7 万字符
- 参数：368 万
- 结果：train 降至 0.81，val 从 step 500 起一路涨到 6.64。模型在背课文。

**第二次尝试（成功：缩小模型）**
- 参数：95 万
- 结果：val loss 最低 4.99。不再严重过拟合。

**第三次尝试（成功：扩大数据）**
- 数据：82 万字符
- 参数：660 万
- 结果：val loss 最低 4.20，train 3.25。参数量与数据量匹配。

## 5. Web 部署与调参技巧

### 5.1 运行方式
python app_zh.py
浏览器打开 http://127.0.0.1:5000

### 5.2 关键推理参数（决定生成质量）
- temperature: 推荐 1.0 ~ 1.2。低于 0.8 时模型只会输出无意义的短对话；高于 1.2 时开始胡言乱语。
- top-k: 推荐 60 ~ 80。配合高温度，能让模型从更大的候选词中采样，写出有叙事、有心理描写的小说段落。

### 5.3 中文模型生成的文本特点
- 能正确使用《四世同堂》的真实人物：冠晓荷、大赤包、小崔、丁约翰
- 能正确使用《骆驼祥子》的人物：祥子、虎妞
- 对话格式符合中文小说规范：引号、冒号、问号一应俱全。

## 7. 踩坑与经验总结

1. **显存控制（GTX 1060 3GB 极限操作）**：中文模型 batch_size=16, n_embd=192, n_layer=6 时显存占用约 800MB。如果模型再大，必须降 batch_size，否则必定 OOM。
2. **数据清洗的底线**：中文千万不要随便过滤低频字，否则文本会变成乱码。只需用正则 ^\s+ 清理行首缩进。
3. **模型参数与数据量匹配原则**：每个参数至少需要 10-20 个字符的训练数据。
4. **早停的重要性**：训练后期可能在 train loss 持续下降时，val loss 开始反弹。加入最佳模型保存机制能多拿到 0.1-0.3 的提升。
5. **从零训练的成就感**：完整走通了数据准备、模型定义、训练循环、模型保存、Web 部署的全流程，比单纯调用 API 做套壳应用更有价值。
